# 合成器 — 扩展接缝

> [English version / 英文版本](EXTENDING.md)

状态：**仅有接缝**。nkdhr 的交互设计正在重新设计，目前不存在任何交互层。本文确定
未来的交互层在何处接入 `nkdhr-compositor`，以及它必须保持哪些不变量，使得交互层
到来时协议层无需重写。本文刻意不谈该层将会做什么。

协议层自带一套永久的默认行为：居中放置、窗口映射时与被点击时获得焦点、由客户端
发起的移动与调整大小、客户端装饰，以及 VT 切换（见
[USAGE_zh_CN.md](USAGE_zh_CN.md#窗口行为)）。其中每一部分都位于下文某一个接缝
之后。未来的交互层通过替换某个接缝处的实现来替换对应的部分；在它这样做之前，
默认行为继续生效。先前的交互层已于 2026-10-23 移除，保存在 git 标签
`archive/interaction-v1` 中，仅供参考；其中任何内容都不构成承诺。

## 接缝

### 初始放置

`windows::initial_location(geometry, &OutputLayout, pointer)` 是唯一决定新窗口
放在哪里的地方（见 [INTERNALS_zh_CN.md](INTERNALS_zh_CN.md#初始放置规则)）。
每次映射它恰好被调用一次：xdg toplevel 提交其第一个缓冲区时（以空缓冲区取消映射
之后会再次发生），以及 X11 受管窗口映射时。对于因输出布局变化而不再位于任何输出
上的窗口，保持可达规则也会调用它（见
[INTERNALS_zh_CN.md](INTERNALS_zh_CN.md#保持可达规则)），因此替换实现同样决定
这些重新定位。替换实现：

- 返回合成器全局逻辑坐标中的一个位置，作为窗口根表面原点的位置；
- 可以参考窗口、布局、指针以及自身的状态，但不会作为副作用移动任何其他窗口；
  重新排列其他窗口是通过窗口存储进行的另一项独立操作；
- 不得假设存在输出：布局可能为空。

override-redirect 的 X11 窗口不由此函数放置；它们保持各自客户端给出的位置。

### 焦点策略

焦点策略由 `state.rs` 中每次焦点变化都要经过的那些函数组成：
`App::focus_window`（聚焦窗口并将其提升到最顶层，用于映射时和点击时）、
`App::focus_topmost`（获得焦点的窗口消失时的回退）和 `App::focus_popup_root`
（持有焦点的菜单弹出窗口抓取链关闭时焦点的去向：该链的根窗口，否则执行回退），
再加上输入路由器中的点击规则（`input::click_to_focus`）。未来的交互层可以通过
修改或替换这些函数，来改变窗口何时获得焦点或被提升、增加其他移动焦点的方式，
或改变回退行为。它要保持这些函数承担的协议义务：

- 窗口上的实时键盘焦点只能通过 `App::set_keyboard_focus` 设置：该函数经由 seat
  的 `KeyboardHandle` 设置焦点，使 `SeatHandler::focus_changed` 保持 xdg 激活
  状态、X11 激活状态与选区焦点三者一致，并在焦点被清除时自行执行同样的簿记
  （Smithay 0.7 不会报告焦点被清除）；
- 会话锁定期间，策略写入的是 `focus_before_lock`，绝不是实时焦点；
- override-redirect 窗口和未放置的 toplevel 永远不会成为焦点目标；
- 提升窗口可能改变指针下方的内容，因此包含提升操作的变更在完成后要刷新指针焦点
  （见下文的窗口存储）。

### 输入路由器

`input::handle(app, &OutputLayout, event)` 是输入的唯一入口。它的处理顺序是
固定的：

1. 锁定路径，它在其他任何步骤运行之前就返回；
2. VT 切换拦截，位于键盘过滤器内部；
3. **挂钩点**：交互层自己对事件的处理；
4. 默认路由：转发给 seat，外加点击聚焦规则。

没有注册 API。未来的交互层直接写进路由器的第 3 步。它可以消费一个事件（例如
用来驱动它自己的指针抓取）、修改事件，或者让事件继续进入第 4 步。由合成器拥有
的指针交互以 Smithay `PointerGrab` 的形式实现，正如 `grabs.rs` 对移动和调整大小
所做的那样，以便抓取的开始、取消以及锁定路径表现一致。

转发时还会记录最近一次按键按下、按键释放、按钮按下和触摸按下，以及它们各自到达
的客户端（`App::user_actions`）；`xdg_popup.grab` 只有对应其中之一时才会被接受。
消费了此类事件的交互层要把它记录为未到达任何客户端，这样在用户做别的事情时，
较旧的 serial 就无法打开菜单。

当一次触摸在当前打开的弹出窗口抓取链所属客户端之外开始新的触摸序列时，默认路由
还会解除该链（`App::dismiss_popup_grab`），就像 Smithay 的 `PopupPointerGrab`
对链外的点击所做的那样。消费了这种触摸按下事件的交互层要以同样的方式解除该链，
使菜单绝不会在别处发生触摸时仍保持打开。

### 渲染元素列表

`render::output_elements` 为每个输出构建元素列表，`render.rs` 中的
`render_elements!` 枚举列出了所有元素种类。未来的交互层向该枚举添加自己的变体，
并把自己的元素插入列表中的确定位置（窗口之上、光标之下，或窗口之下）。两个后端
绘制的是同一份列表，因此新的元素种类无需修改后端即可在两者上工作，前提是它与
渲染器无关：任何元素类型都不得指名某个具体的渲染器。

### 窗口存储

`WindowStore`（`windows.rs`）是客户端窗口的唯一列表：记录它们的 id、位置、层叠
顺序和放置状态，并提供放置、提升、移动、查找窗口以及对全局坐标点做命中测试的
操作。未来的交互层只通过它读取和修改窗口。它可以保存以 `WindowId` 为键的自有
数据（id 永不复用），也可以添加存储操作，但绝不另外保存一份协议层看不到的窗口、
位置或层叠顺序列表。

在 Smithay 中，指针焦点只随指针移动而变化。因此，凡是改变静止指针下方内容的变更
（放置、提升、移动、取消映射或移除窗口），都要在整个变更完成后调用
`input::refresh_pointer_focus`，与协议层自身的变更一样（见
[INTERNALS_zh_CN.md](INTERNALS_zh_CN.md#输入路由)）。不得在指针抓取自身的回调
内部调用它：移动窗口的抓取把焦点留到抓取结束时处理，正如 `grabs.rs` 所做的那样。

### 输出布局

`OutputLayout`（`outputs.rs`）是已连接的各个输出在合成器全局逻辑空间中解析后的
排布，每当输出或配置发生变化时，都会根据 `outputs` namespace 重新构建。未来的
交互层读取它，并可以在其上定义自己的坐标空间，但在触及窗口存储、seat 或任何
协议对象之前，要先转换为全局逻辑坐标。输出排布本身仍由 `outputs` namespace
负责。

每个新布局都通过 `App::set_output_layout` 到达协议层，该函数同时应用保持可达
规则（`windows::location_to_keep_reachable`）。若交互层要改变布局变化时窗口的
处理方式，就在那里修改，并保持该规则向用户提供的保证：任何窗口都绝不会被留在
没有任何输出显示它的地方。

新的持久化设置放入它们自己的 CTRL-5 namespace。`Config1.Set` 只会覆盖已经存在
的值，因此对于 key 在运行时才产生的设置（每个输出一个条目、每个窗口类一个条目
等），要通过写入该 namespace 的文件来创建，之后再通过 `Set` 调整，`outputs`
正是这样做的。

## 不变量

无论做什么，每个扩展都要保持以下各项：

- **协议层拥有一切协议事实。** 表面角色、configure/acknowledge 循环、初始
  configure、经由 seat 投递的键盘与指针焦点、`wl_surface` 的输出归属、首选缩放
  比例、帧回调、选区、XWayland 窗口管理器职责、屏幕捕获（screencopy）以及锁定
  状态，都由协议层维护。策略只请求一个结果（把这个窗口放在这里、聚焦那个窗口、
  请求这个尺寸），由协议层将其转化为协议通信。任何策略都不会自行发送协议事件。
- **策略绝不绕过窗口存储。** 客户端在屏幕上看到的每个窗口都在存储中，位于存储
  记录的位置，按存储记录的顺序排列。渲染、命中测试、输出归属和帧回调都读取该
  存储，因此任何绕过它的做法都会让告知客户端的内容与用户看到的内容失去同步。
- **会话锁路由保持 fail-closed。** 锁定路径在挂钩点之前运行，其本身不是挂钩点。
  锁定期间，不渲染任何策略元素，任何策略抓取都不能在锁定开始后存续，也不能在
  锁定期间启动，任何策略都不接收输入，屏幕捕获只暴露锁定画面的合成结果。持有
  键盘、指针或触摸抓取的策略必须让会话锁结束这些抓取，就像会话锁已经对 Smithay
  的抓取和进行中的触摸序列所做的那样。
- **VT 切换始终可达。** VT 切换拦截在挂钩点之前运行，锁定路径和未锁定路径中都是
  如此，任何策略都不得消费 `Ctrl+Alt+F1`…`F12` 或 `XF86Switch_VT_1`…`12`。它是
  用户脱离卡死会话的出路。
